## 4. Находки

Формат: **где** → что происходит → последствие → что сделать.

### A. Высокий приоритет

**A1. Бан собственного IP отрезает оператора от сервера.**
`modules/src/security/actions.rs::ban` — IP проверяется только на синтаксис. Кнопка «бан» есть в таблицах атакующих, соединений и аномалий; адрес оператора может оказаться среди «атакующих» после нескольких неудачных входов или в топ-пирах по числу соединений. Через nftables/iptables бан применяется мгновенно к цепочке `input`, включая SSH, — приложение теряет сессию и не может выполнить `unban`. Сделать: перед баном сравнивать цель с адресом клиента текущей сессии (`echo $SSH_CLIENT` / `who am i` одной командой) и с адресами из `spec.jump`; при совпадении отказывать с понятной ошибкой. В nft-правило добавить исключение для SSH-порта или `ct state established` — тогда даже ошибочный бан не рвёт живые сессии.

**A2. Обрыв SSH во время `detect` оставляет сервер «Online» без модулей на 10 минут.**
`engine/src/test_connection.rs::detect_one` превращает любую ошибку, включая `TransportError::Disconnected`, в `Availability::Unavailable`. `worker/mod.rs::spawn_collectors` тогда не запускает ни одной задачи, watch-канал `lost` никто не дёргает, `serve` ждёт `REDETECT_INTERVAL` (600 с) со статусом `Online`. Пинг при этом показывает потери, но переподключение не запускается. Сделать: в `detect_one` пробрасывать `Disconnected` наверх (вернуть `Result`), а в `serve` при ошибке — сразу возвращать причину; дополнительно, если после `detect_all` нет ни одного usable-модуля при живой сессии — это тоже повод не ждать 10 минут.

**A3. Проверка «Пустые пароли» без root показывает «нет» вместо «пропущено».**
`modules/src/security/mod.rs` секция `shadow`: `[ -r /etc/shadow ] && awk …` печатает пусто, если файл нечитаем; `hardening.rs::parse` делает `sections.get("shadow").map(lines)` → `Some(vec![])`; `incidents/src/audit/patterns/access.rs::empty_passwords` считает `Some([])` за Pass. Итог: на сервере без sudo оценка безопасности завышена, а реальные пустые пароли не видны. Сделать: печатать маркер недоступности (`[ -r /etc/shadow ] || echo '@@unreadable'`) и превращать его в `None`, либо использовать `is_root_view` при разборе. Проверить тем же способом `nopasswd` (там `[ -r /etc/sudoers ] && …` даёт `None`, это правильно) и `keyperms`.

### B. Средний приоритет

**B1. Переименование сервера создаёт дубликат.**
`ui/pages/server_form/model.rs::build` допускает новое имя при редактировании; `engine/src/engine/mod.rs` `Command::UpdateServer` → `save_and_start` сохраняет новый toml и стартует новый воркер, старый воркер, `ServerState`, toml, `.md`, `.llm.md` и записи keyring остаются. Сделать: либо запретить менять имя в форме (`editing.is_some()` → поле read-only), либо в движке при `spec.id != old_id` вызывать `remove(old)` с переносом секретов и документов. ТЗ 4.3 требует переименование файлов.

**B2. Удаление сервера не удаляет `<id>.llm.md` и не чистит историю.**
`config/src/server_store.rs::delete` перебирает `[spec_path, doc_path]` — `llm_doc_path` забыт. Сэмплы и журнал действий в SQLite остаются навсегда (в пределах retention для сэмплов, вечно — для `actions`). Сделать: добавить `llm_doc_path` в список; в `StorageWriter` — запрос `DeleteServer(id)`.

**B3. Даунсэмплинг SQLite впервые запускается через час после старта.**
`storage/src/writer.rs`: `last_maintenance = Instant::now()` при спавне, `MAINTENANCE_INTERVAL = 3600`. Если приложение живёт сессиями короче часа, `samples` растёт без ограничения (Fast-модули дают ~30 сэмплов/с на сервер → ~2,5 млн строк в сутки на сервер). Сделать: выполнять `maintain` при старте потока и далее по расписанию.

**B4. Изменение сроков хранения в настройках не доходит до хранилища.**
`ui/app/actions.rs` `Action::SaveCollection` сохраняет `retention` в `config.toml` и шлёт только `Command::SetIntervals`. `StorageWriter` получает `Retention` один раз при спавне (`asiba-app/src/main.rs`). Действует после перезапуска, пользователю это не сообщается. Сделать: `Command::SetRetention` → сообщение в поток записи; заодно убрать дублирование типа `Retention` (`asiba-config::Retention` и `asiba-storage::Retention` — две одинаковые структуры, конвертируются вручную в `main.rs`).

**B5. Алерты по правилам не учитывают возраст последнего значения.**
`alerts/src/evaluator.rs::metric_value` берёт `series.latest()` без проверки времени. Сервер ушёл в offline с CPU 95 % — алерт `cpu-high` висит, пока сервер не вернётся; вместе с `offline` это два инцидента на одну причину. Аналогично для модуля, отключённого после трёх ошибок: его последнее значение «замораживается». Сделать: пропускать правило, если точка старше, например, трёх интервалов расписания модуля (или если сервер не online для всех метрик, кроме `connection.offline`).

**B6. Инцидент «OOM killer» — по счётчику с загрузки и никогда не закрывается сам.**
`incidents/src/detectors/memory.rs`: `oom_kills > 0` из `/proc/vmstat` — накопительный с boot. Один OOM месяц назад = постоянный warning-инцидент, который можно только «забыть». То же — паттерн `resources.oom`. Сделать: детектировать прирост относительно предыдущего снимка (модуль `memory` уже создаёт событие на прирост) и держать инцидент открытым ограниченное время, либо считать с момента старта приложения.

**B7. Модуль `deploy` не включается, если единственный источник — лог-файл из настроек.**
`modules/src/deploy/mod.rs::detect` вызывает `detect_script(&[])`: `Module::detect` не получает `CollectContext`, поэтому пути из `[modules.deploy] logs` в проверке не участвуют. На сервере без docker, `deploy*`-юнитов и раннера модуль будет `Unavailable`, хотя `MODULE_GUIDE.md` обещает «наличие логов из настроек». Сделать: передавать настройки в `detect` (изменение трейта — запись в DECISIONS) или включать модуль, если настройка задана.

**B8. Модуль `git` сканирует файловую систему и гоняет `git status` каждые 20 секунд.**
`modules/src/git/script.rs`: `find /opt /srv /var/www /home/* /root /app /docker /data -maxdepth 3` + по каждому репозиторию 9 команд, включая `status --porcelain` и `log -100`. На сервере с десятком репозиториев и большими `/home` это заметная нагрузка на IO и CPU при том, что данные меняются редко. Сделать: `Schedule::Slow` (5 мин) или кешировать список репозиториев между сборами и пересканировать раз в N сборов.

**B9. `updates` вызывает `dnf check-update` каждые 5 минут.**
`modules/src/updates/mod.rs`, `Schedule::Slow` = 300 с по умолчанию. `dnf check-update` при устаревшем кеше метаданных ходит в сеть и может занимать десятки секунд и сотни МБ памяти; `apt-get -s upgrade` дешевле, но тоже не бесплатен. Сделать: отдельный интервал для `updates` (например, 1 ч через `interval` по умолчанию) или `dnf -C check-update` (только кеш) с редким полным обновлением.

**B10. `security` каждые 20 секунд читает 24 часа журнала sshd.**
`modules/src/security/mod.rs`: `journalctl --since -24h -t sshd -t sshd-session -n 2000` + `-t sudo -n 500` + `sshd -T` + `sha256sum` + `find` по `/home/*/.ssh` и `/etc`. На сервере под перебором это до 2 000 строк парсинга каждые 20 с. Данные (кроме входов) меняются редко. Сделать: инкрементальный сбор журнала по курсору, как в `logs`, либо разнести: входы — Normal, hardening/sshd/hashes — Slow.

**B11. Ключ API провайдера ИИ хранится открытым текстом в `config.toml`.**
`config/src/ai_config.rs`: `api_key: String` сериализуется в `~/.config/asiba/config.toml` (права файла — умолчание `umask`, обычно 644). Пароли серверов при этом в keyring. Сделать: хранить ключ в keyring (`asiba`, аккаунт `ai/<provider>`), в toml — только признак наличия.

### C. Низкий приоритет

**C1. `systemctl stop` с ошибкой отчитывается как успех.**
`modules/src/services/actions.rs::perform`: команда `systemctl stop U && systemctl is-active U` при упавшем `stop` (например, нет прав или юнит защищён) даёт ненулевой код, который `or_else` для `stop` превращает в `"inactive"`. Сделать: `systemctl stop U; systemctl is-active U || true` с проверкой кода первой команды отдельно.

**C2. Ручное «Переподключить» и смена интервалов стирают снимки и серии сервера.**
`engine/src/engine/workers.rs::start_worker` всегда вставляет `ServerState::new(spec)`. Скорости на один интервал показывают «—», лента событий сервера и серии в памяти очищаются (история из SQLite подставляется за 30 мин, но до 5 с несброшенных сэмплов теряется). DECISIONS от 2026-09-17 обещает сохранение снимков при переподключении — это верно только для автоматического реконнекта внутри воркера. Сделать: при перезапуске переносить `modules`, `series`, `recent_events` из старого состояния.

**C3. Пинг не работает через jump host.**
`engine/src/worker/ping.rs` соединяется с `spec.host:port` напрямую. Для сервера за бастионом пинг всегда «потерян», `lost_in_row` растёт бесконечно, линия на карте — без RTT. Сделать: при `spec.jump.is_some()` пинговать jump host (с пометкой) или измерять RTT по SSH-keepalive/времени пустой команды.

**C4. Аргумент действия до 120 символов пишется в журнал целиком.**
`engine/src/actions.rs::journaled_argument` — README обещает «содержимое файла в журнал не попадает — только размер», но короткое содержимое (например, `.env` с паролем БД в 100 символов) сохраняется в SQLite и показывается в настройках. Сделать: для `files::ACTION_WRITE` всегда писать только размер.

**C5. Запись файла не атомарна, и «Сохранить файл» — обычное, а не опасное действие.**
`modules/src/files/script.rs::write`: `printf '%s' … > file` — при обрыве файл будет усечён; при этом `write` в `/etc/fstab` или `/etc/ssh/sshd_config` на production-сервере требует ввода имени только благодаря окружению. Сделать: писать во временный файл рядом и `mv` поверх (сохраняя права через `cp --attributes-only` или `chmod --reference`); `Danger::High` для путей под `/etc`, `/boot`, `/usr` либо для всех записей.

**C6. `AppState.audits` растёт без ограничения.**
`engine/src/ai/worker.rs::open` и `engine/audits.rs::enqueue_report` только добавляют; при автоанализе разделов и инцидентов список за долгую сессию накапливает сотни отчётов с полным текстом. Сделать: `trim_audits` по аналогии с `trim_resolved_alerts` (оставлять последние N на `target:scope`).

**C7. `systemd_time` для именованных зон подставляет UTC.**
`modules/src/common/systemd_time.rs::normalize_zone`: `Mon 2026-09-14 12:30:00 MSK` → трактуется как `+0000`. На серверах с локальной зоной `ActiveEnterTimestamp` юнитов и таймеры сдвинуты на смещение зоны. Сделать: запрашивать `systemctl show` с `TZ=UTC` в скрипте (`env TZ=UTC systemctl show …`) — тогда всегда `UTC`.

**C8. Сводки «за сутки» в файле сервера — на самом деле за ~30 минут.**
`docgen/src/series_stats.rs` считает окна `HOUR` и `DAY` по кольцу `Series` (900 точек ≈ 30 мин для Fast) с предзагрузкой из базы тоже за 30 мин (`engine/history.rs::PREFILL_WINDOW`). Столбцы «час» и «сутки» совпадают, а модель получает вводящие в заблуждение подписи. Сделать: считать окна по `samples_1m`/`samples_1h` из SQLite (через `HistoryReader`) или честно называть окно по фактическому охвату серии.

**C9. Геолокация и страны IP уходят на `ip-api.com` по HTTP без согласия.**
`engine/src/geo.rs`, `engine/src/peers.rs`: адреса всех серверов и до 100 IP атакующих отправляются стороннему сервису открытым HTTP сразу после старта. Для ИИ есть галочка согласия, здесь — нет. Сделать: настройку «геолокация через ip-api.com» (по умолчанию включена, но видимая) и упоминание в README рядом с «что уходит наружу».

**C10. Проверка «доступен снаружи» для `localhost` бессмысленна.**
`modules/src/ports/reachability.rs` соединяется с `context.host`; для локального сервера это `127.0.0.1`, и все слушающие порты «доступны снаружи», а паттерн `firewall.exposed_ports` даёт ложные провалы. Сделать: пропускать проверку для `spec.is_local()` (host пустой → `fill` уже возвращается рано; передавать пустой хост для локального).

**C11. Контейнер, завершившийся с ошибкой без политики перезапуска, — вечный critical.**
`incidents/src/detectors/containers.rs::down`: `exit_code != 0` без `restart_policy` — например, разовый `docker compose run migrate`, упавший неделю назад, — critical-инцидент, пока контейнер не удалят. Сделать: для контейнеров без политики перезапуска понижать до warning и учитывать давность (`status: Exited (1) 6 days ago`).

**C12. `system_audit` пересчитывается каждый кадр на вкладке «Безопасность» и в её виджете сводки.**
`ui/pages/server_detail/security/mod.rs`, `ui/modules/security/mod.rs`: 77 паттернов × 60 кадров/с, часть паттернов итерирует все порты/юниты/контейнеры. Ощутимо на слабых машинах при открытой вкладке. Сделать: кешировать `SystemAudit` в `egui` temp data по `(server, last_collected)` или считать в цикле алертов и класть в `AppState`.

**C13. Расписание `system` — Normal (20 с), а не Slow.**
`modules/src/system/mod.rs` — `Schedule::Normal`; `ARCHITECTURE.md` относит system к Slow. Данные (ОС, ядро, CPU-модель) меняются раз в месяцы, uptime/load дублируются другими модулями. Сделать: `Slow` и поправить документ (или наоборот).

**C14. Правила `CLAUDE.md` о размере нарушены в 60 местах.**
2 файла длиннее 300 строк, 58 функций длиннее 40 строк (см. раздел 2). Большинство — таблицы констант (`builtin_rules`, `script()` модуля security, `SCRIPT_PARTS`) и egui-раскладки, где разбиение ухудшит читаемость. Сделать: либо явно разрешить в `CLAUDE.md` исключение для «функций-таблиц» и UI-раскладок, либо разбить самые длинные (`app/actions.rs::apply` 106 строк — по группам действий; `server_form/mod.rs::connection_fields` 87 — auth / jump / sudo).

## 6. Качество кода

**Сильные стороны.** Чёткое разделение на крейты без обратных зависимостей; трейты `Module`/`Transport`/`Section`/`Detector`/`Pattern` дают предсказуемый способ расширения; парсеры — чистые функции с фикстурами реального вывода; ошибки типизированы; все команды на сервере собраны в одном месте на модуль и задокументированы; действия валидируют цели и экранируют аргументы; UI не трогает сеть. Идиоматичный Rust 2024 (`let … else`, `let`-chains, `is_none_or`), без `clone()` без нужды.

**Слабые места.**
- Тесты покрывают парсеры (141 в modules), но почти не покрывают движок (6 тестов на 2 662 строки: нет тестов жизненного цикла воркера, реконнекта, backfill, очереди ИИ) и `asiba-incidents` (9 тестов на 77 паттернов и 12 детекторов — паттерны тестируются только на уникальность id и наличие текстов, логика `evaluate` не проверяется).
- `asiba-ui` — 12 948 строк, треть проекта; тесты только на чистые функции. Ручного QA-чеклиста нет.
- Дублирование: `Retention` в двух крейтах; `Severity → Urgency` и формат уведомления дважды в `alerts/notify.rs`; `is_private`/`is_public` для IP в `geo.rs` и `peers.rs`.
- Нет CI-конфигурации в репозитории и `cargo deny` (ТЗ 11).
